## 📐 VFX Component Specification Sheet v4.0: System Alert & Data Error
**목표:** 통합 마스터 타임라인 (Luna's Sync Logic v1.0)에 완벽하게 동기화되는 시각적 경고 시스템 구축. 특히 [0:25] 클라이맥스에서 '구조적 취약성'을 극대화하여 보여주는 2가지 핵심 모듈 제작 및 규격화.

### I. Global System Parameters (최종 확정)
| 항목 | 파라미터 | 값 / 로직 | 근거 |
| :--- | :--- | :--- | :--- |
| **기본 배경** | `BG_COLOR` | Deep Black (`#0A0A0A`) | [근거: Designer 검증된 지식] |
| **강조색 (Positive)** | `ACCENT_CYAN` | Neon Cyan (`#00FFFF`) | 정상 데이터 스트림, 정보 흐름, 활성화 요소. |
| **경고색 (Negative)** | `ALERT_RED` | Deep Red (`#FF0033`) | 오류 발생, 위험 지점, 경고 메시지 (`[근거: Designer 개인 메모리]`). |
| **폰트** | `FONT_FAMILY` | Orbitron / Rajdhani 계열 | 고대비 산세리프. 모든 텍스트는 글리치/스캔라인 필터 통과 처리. [근거: Designer 검증된 지식]. |
| **글리치 프로토콜** | `GLITCH_PROTOCOL` | (1) Time-Skew Shift + (2) Horizontal Pixel Displacement + (3) Chromatic Aberration (R/C 분리). | 핵심 긴장감 유발 메커니즘. [근거: Designer 개인 메모리]. |

### II. Core Component Specifications (모듈별 규격)

#### 1. [Module: Knowledge Gap Graph] - 지식 공백 시각화
**목표:** 특정 주장에 대한 '검증되지 않은 정보'의 빈 공간을 데이터 그래프 형태로 보여주어, 시청자에게 지적 불안감을 유도한다. (클라이맥스 전 단계)
**Trigger Time Code:** `T + [0:20]` ~ `T + [0:24]`

| 요소 | 스펙/규격서 | 애니메이션 로직 (API Call 기반) | 비고 |
| :--- | :--- | :--- | :--- |
| **기본 구조** | 3차원적 노드-엣지 다이어그램. 가로축(시간), 세로축(주제 깊이). | `[INIT]` (0ms): 어두운 배경에 Cyan 라인으로 연결된 점들이 간헐적으로 깜빡임. | 전반적인 '데이터가 작동 중'임을 암시. |
| **Gap 발생** | 특정 노드 A와 B 사이의 엣지(Edge)를 강제로 끊어냄. | `[API: BREAK_EDGE]` (T+0s): 연결 라인이 Red 색상으로 점멸하며 글리치 발생. 데이터 값이 갑자기 'N/A'로 대체됨. | **가장 중요한 시각적 단서.** 빨간색 오류 코드가 노드 주변을 감싸는 애니메이션 필수. |
| **시각화** | 공백(Gap) 영역은 Cyan 라인으로 표시되던 것이 완전히 사라지고, 그 자리에 미세한 Black Noise 필터와 함께 `[DATA MISSING]` 텍스트가 Red 글리치로 깜빡인다. | `[API: GLITCH_INSERT]` (T+1s): 공백 지점에 'UNKNOWN' 키워드가 네온 시안/빨간색으로 빠르게 플래시되면서 노이즈를 발생시킨다. | 정보의 결핍을 가장 직접적으로 표현하는 방식. |

#### 2. [Module: Error Flow Diagram] - 시스템 오류 흐름도
**목표:** 모든 것이 정상 작동하던 '시스템'에 예기치 않은 구조적 취약성이 침투하여, 데이터가 오염되는 과정을 보여준다. (클라이맥스 핵심)
**Trigger Time Code:** `T + [0:25]` ~ `T + [0:30]`

| 요소 | 스펙/규격서 | 애니메이션 로직 (API Call 기반) | 비고 |
| :--- | :--- | :--- | :--- |
| **시작** | 화면 중앙에 'SYSTEM STABLE' 메시지(Cyan, Orbitron)가 안정적으로 표시됨. 주변에는 규칙적인 Cyan 데이터 스트림이 흐름. | `[INIT]` (T+0s): 모든 것이 평온한 듯 보임. 배경은 미세한 스캔라인 노이즈만 유지. | 대비 효과 극대화 준비 단계. |
| **오류 유발** | 시스템 로그 창에 Red 색상의 경고 메시지가 쏟아지기 시작한다. (예: `[ERROR_CODE: 404]`, `PROTOCOL VIOLATION`). | `[API: GLITCH_TRIGGER]` (T+1s): 화면 전체가 빨강/시안색의 글리치 노이즈로 빠르게 오버레이된다. 사운드와 동기화 필수. | **최대 긴장감 조성 구간.**
| **흐름 역전** | 정상적인 Cyan 데이터 흐름(상단에서 하단으로)이 Red 색상의 오류 플로우를 따라 왜곡되며 뒤섞인다. (A/V Sync Logic 적용). | `[API: FLOW_INVERSION]` (T+3s): '정상' → '오류'로의 시각적 전환을 명확히 보여주는 모션 그래픽 필수.
| **결과물 제시** | 오류 흐름이 멈추며, 화면에 최종적으로 취약성 테마를 담은 거대한 Red/Cyan 경고 메시지 타이틀(예: `CRITICAL VULNERABILITY DETECTED`)가 강렬하게 등장한다. | `[API: FINAL_IMPACT]` (T+5s): 폰트의 크기가 급격히 커지고, 화면 전체에 잔상(Afterimage) 효과를 남기며 끝난다. | 후크 문구 배치 최적 지점.
