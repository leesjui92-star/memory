### 💾 최종 CTA 임팩트 모듈 디자인 브리프 (Shorts/9:16)

이 모듈은 영상의 흐름을 끊고, 강렬한 심리적 충격(Shock Value)과 시스템적인 경고를 동시에 전달하는 것이 목표입니다.

#### 1. 핵심 콘셉트 및 원칙
*   **테마:** 지식 만료 공포 (Knowledge Obsolescence Fear) / 프로토콜 실패 (Protocol Failure).
*   **핵심 감정:** 즉각적인 위협, 시간적 압박, 정보의 부족함.
*   **발동 조건:** 스크립트 내에서 '위험 요소'가 언급되거나, 핵심 지식이 공개되기 *직전*.
*   **배경/톤:** 기존 Deep Black (`#0A0A0A`) 배경을 유지하되, 전반적인 화면에 미세한 **글리치 노이즈 레이어**를 오버레이하여 시스템 불안정성을 강조합니다.

#### 2. 비주얼 요소 상세 명세 (Component Breakdown)
| 컴포넌트 | 사양 (Specification) | 색상 코드 및 효과 | 목적/기능 |
| :--- | :--- | :--- | :--- |
| **A. 경고 타이머** | 디지털 방식, 카운트다운 형식 (`00:03`) | **Neon Red (`#FF4444`):** 시간 감소 시점마다 깜빡임(Blinking) 효과 필수. <br>**글리치:** 숫자가 갱신될 때마다 짧은 스캔라인 노이즈 발생. | 시간적 압박감 극대화. 행동의 지연을 허용하지 않음. |
| **B. 핵심 경고 UI** | 화면 중앙 상단에 '시스템 경고' 박스 배치 (좌측/우측 앵커 활용) | **Neon Cyan (`#00FFFF`):** 시스템 메시지, 프로토콜명 강조.<br>**Red (`#FF4444`):** 위험 수준(CRITICAL) 표시. | 정보의 위협성 및 전문성을 높임. '어딘가에 문제가 있다'는 인지 유도. |
| **C. 타이포그래피 (헤드라인)** | 고대비 산세리프 (`Orbitron` 또는 `Rajdhani`) 사용. 3~4줄 구성. | **Neon Cyan/Red 조합:** 문장 단위로 색상 변경 및 글리치 효과 적용. | 시청자의 집중을 강제로 유도하고, 지적인 충격파를 전달. |
| **D. 콜투액션 (CTA) 영역** | 모듈 하단 1/3 지점 배치. 버튼 형태보다 '데이터 스트림'처럼 보이게 디자인. | **Neon Cyan:** 활성 링크 강조. `[SYSTEM_LINK]`와 같은 시스템 용어 사용. | 클릭을 자연스러운 '정보 해독 과정'의 일부로 만듦. |

#### 3. 시간 코드 기반 시각적 가이드 (Time-coded Visual Guide)
개발자가 테스트할 수 있도록, 이 모듈이 영상에 등장해야 하는 표준적인 시간 흐름(Flow)을 정의합니다.

| 시간대 ($t$) | 길이 ($\Delta t$) | 발생 이벤트 / 비주얼 트랜지션 | 목표 및 개발자 검증 포인트 |
| :--- | :--- | :--- | :--- |
| $t_{start}$ (T-2초) | 1.5s | **[Pre-Alert]:** 화면 전체에 미세한 노이즈/스캔라인 오버레이 증가. 배경 음악의 저음역대 떨림(Sub Bass Hum) 추가. | **[검증 포인트]**: 비주얼 시스템 변화가 트래킹 가능한지 확인 (노이즈 레이어 전환). |
| $t_{Alert}$ (T-0초) | 2.5s | **[Module Trigger]:** 경고 UI(B)와 타이머(A)가 동시에 폭발적으로 등장. 배경 색상이 Deep Black $\rightarrow$ Dark Gray로 미세하게 변이. 중앙에 `PROTOCOL FAILURE` 등의 메시지 글리치 오버레이. | **[검증 포인트]**: 1. A/B 테스트 게이트웨이 진입 여부 확인. 2. 모듈 등장 시점의 트래킹(Time Stamp) 정확성 검증. |
| $t_{CTA}$ (T+0초) | 3.0s | **[Critical Info]:** 경고 UI가 축소되며, 중앙에 최종 CTA 메시지(C)와 링크 영역(D)이 등장. 타이머는 카운트다운을 지속적으로 보여주며 긴장감을 유지. | **[검증 포인트]**: 1. 이 시점의 UTM 트래킹 활성화 확인. 2. 모듈 퇴장 전까지 데이터 로그가 안정적으로 기록되는지 검증. |
| $t_{end}$ (T+3초) | 0.5s | **[Deactivation]:** 모든 경고 UI와 타이머가 빠른 속도로 '시스템 종료'되듯 사라짐(Fade Out/Glitch Dissolve). 배경 노이즈 제거. | **[검증 포인트]**: 모듈 해제 시점의 시스템적 안정성 확보 (데이터 로그 끊김 방지). |

## 🎯 목표 및 콘셉트
*   **목표:** 지식 만료 공포(Knowledge Obsolescence Fear)를 기반으로 트래픽을 유도하는 시스템적 경고.
*   **톤앤매너:** 테크-느와르, 긴장감, 위협적 전문성.

## 🎨 비주얼 요소 스펙 (Component Specs)
1.  **배경 원칙:** Deep Black (`#0A0A0A`) 기반 + 미세한 노이즈/스캔라인 오버레이(전 구간).
2.  **핵심 컬러 팔레트:**
    *   Primary: Neon Cyan (`#00FFFF`) - 정보, 활성화된 데이터.
    *   Alert: Neon Red (`#FF4444`) - 경고, 위험 수준.
3.  **타이머 (A):** 디지털 글리치 카운트다운. 배경은 `Deep Black`에 대비되는 밝은 네온 텍스트. 시간 감소 시 깜빡임 필수.

## ⏱️ 타임라인 및 개발자 검증 가이드 (Time-Coded Flow)
| Time Code | Event Description | Visual/Audio Trigger | Developer Test Focus |
| :---: | :--- | :--- | :--- |
| **T-2s** | Pre-Alert Stage | 노이즈 오버레이 증가, 서브 베이스 험(Hum) 사운드 시작. | 비주얼 변화 감지 트래킹 테스트. |
| **T-0s** | Module Trigger (CRITICAL) | 경고 UI 등장 + 타이머 활성화. `PROTOCOL FAILURE` 글리치 오버레이. | UTMT 게이트웨이 진입 검증 및 시간 기록(Time Stamp). |
| **T+0s** | CTA Focus (Link Flow) | 경고 UI 축소, 중앙에 최종 메시지/링크 영역 고정 배치. 타이머 카운트다운 유지. | **[필수]**: 이 시점에서 UTM 트래킹 게이트웨이 활성화 및 데이터 로그 검증. |
| **T+3s** | Module Dissolve | 모든 요소가 빠르게 글리치 방식으로 해제됨 (Glitch Dissolve). | 시스템 종료 및 다음 콘텐츠로의 매끄러운 전환(Seamless Transition) 확인. |
