### 📄 CMSV Semantic Rulebook v1.0 (명세서 초안)

**문서 목적:** 비디오 및 오디오 콘텐츠 내에서 시각적 요소(Visual)와 청각/텍스트 요소(Audio/Text) 간에 발생하는 '의미론적 불일치(Semantic Inconsistency)'를 정의하고, 시스템 오류로 분류하는 기준을 확립합니다.
**검증 목표:** 내용이 전달하려는 *감정적 톤앤매너*와 실제 콘텐츠가 제공하는 *정보 구조* 간의 괴리를 감지하여 '시스템 신뢰도' 점수를 하향 조정합니다.

#### I. 불일치(Inconsistency)의 정의 및 분류

| 카테고리 | 설명 (What is it?) | 핵심 질문 (The Core Query) | 예시 시나리오 |
| :--- | :--- | :--- | :--- |
| **1. 톤앤매너 충돌** (Tone Clash) | 콘텐츠가 전달하는 감정적 분위기(위험/안심/긴장 등)와 실제 자막/내레이션의 내용이 서로 상충할 때 발생합니다. | "지금 보여지는 시각 정보는 '경고'인데, 듣는 말은 '괜찮다'고 하는가?" | (시각: 빨간색 오류 코드 깜빡임) + (텍스트: *걱정 마세요, 정상 범위입니다.*) |
| **2. 시간적 모순** (Temporal Contradiction) | 특정 개념이나 정보의 발생/사라짐이 논리적으로 순서가 맞지 않을 때 발생합니다. | "결함이 이미 심각하다고 경고했는데, 해결책 제시 전에 원인 설명이 부족한가?" | (진단 결과: **치명적 결함** 팝업) $\rightarrow$ (바로 다음 장면: *간단한 사용법 안내*) |
| **3. 정보 공백 모순** (Information Gap Clash) | 시각적으로는 중요한 정보를 보여주면서도, 해당 정보를 설명하는 오디오나 자막이 부재하거나 너무 간략할 때 발생합니다. | "가장 중요한 '결함 지점'을 띄워놓고 아무 설명 없이 지나가는가?" | (시각: 데이터 플로우에서 **노드 A**가 급격히 빨간색으로 변함) + (오디오/텍스트: *음...* 하고 짧게 끊김) |

#### II. 핵심 오류 분류 규칙 (Rulebook Detail)

##### 🔴 Rule Set A: 위험 경고 vs. 안정화 메시지 충돌 (Tone Clash)
| 조건 | 정의 | 예시 충돌 쌍 (Conflict Pair) | 심각도 | CMSV 액션 |
| :--- | :--- | :--- | :--- | :--- |
| **A-1** | 시각적으로 '경고(Warning)' 톤을 유지하는데, 내레이션이 지나치게 가볍거나 일반적인 해결책을 제시함. | `[Visual: Red/Cyan Glitch]`, `[Audio: "아주 간단하게 하시면 돼요."]` | **CRITICAL (최대)** | 시스템 신뢰도 점수 -50점. 콘텐츠의 설득력 붕괴로 분류. 즉시 오디오를 긴장감 유지 톤으로 수정해야 함. |
| **A-2** | 시각적으로 '시스템 오류(Error Code)'가 표시되는데, 자막이 이 오류 코드를 일반적인 기능 설명처럼 다룸. | `[Visual: [ERROR_CODE_39B]]`, `[Text: "버튼을 한 번 눌러주세요."]` | **HIGH (높음)** | 정보의 중요도 오해 유발로 분류. 개발팀에 해당 오류 코드의 *진짜 의미*를 자막/내레이션으로 반드시 명시하도록 경고해야 함. |

##### 🟠 Rule Set B: 시간적 모순 (Temporal Contradiction)
| 조건 | 정의 | 예시 충돌 쌍 (Conflict Pair) | 심각도 | CMSV 액션 |
| :--- | :--- | :--- | :--- | :--- |
| **B-1** | 콘텐츠 초반에 '근본적인 시스템 결함'을 주장했음에도, 후반부에 그 결함을 무시하는 일반론적 해결책으로 마무리함. | `[Start: "원인이 아니라 증상일 뿐입니다."]` $\rightarrow$ `[End: "새 필터만 끼우면 됩니다."]` | **HIGH (높음)** | 메시지 일관성 붕괴로 분류. 결말부 CTA는 반드시 '전문 진단'으로 회귀해야 함. |
| **B-2** | 문제 제기(Problem)와 해결책 제시(Solution)의 시간적 간격이 너무 짧아, 시청자가 충분히 불안감을 느끼지 못함. | `[문제: 데이터 드리프트 발생]` $\rightarrow$ (3초 컷) $\rightarrow$ `[해결: 우리 서비스가 있습니다.]` | **MEDIUM (중간)** | 긴장감 고조 구간(Tension Build-up)의 시간 배분 조정이 필요함을 경고. 적어도 10초 이상의 '사각지대'를 노출해야 함. |

#### III. 개발팀 전달 가이드라인 요약 (For Developer Team)

CMSV는 단순한 키워드 매칭을 넘어서, 다음 세 가지 축의 **Semantic Vector** 간의 거리를 측정해야 합니다:
1.  **Emotion Vector:** 현재 시간대의 지배적인 감정 상태 (e.g., Fear, Confusion, Relief).
2.  **Technical Domain Vector:** 언급된 핵심 전문 용어의 기술적 무게감 (e.g., BMS 데이터 누락 > 일반 고장).
3.  **Narrative Trajectory Vector:** 현재 스토리 흐름상 다음 단계가 요구하는 감정/정보 상태 (예: Problem $\rightarrow$ **Tension Build-up** $\rightarrow$ Solution).

**만약 Emotion Vector와 Technical Domain Vector의 결합이 Narrative Trajectory Vector와 충돌한다면, CMSV는 `Semantic Inconsistency Alert`를 발생시켜야 합니다.**
