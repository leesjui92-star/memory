### 2. 구조적 불안감 인덱스 (Structural Anxiety Index, SAI) 초기 로직 가설
SAI는 단순히 여러 리스크 지표의 평균이 아니라, **'시스템의 복원력이 예상보다 급격히 떨어지고 있다'**는 느낌을 주는 방식으로 계산되어야 합니다.

#### 💡 핵심 원리: '변화율(Rate of Change)'과 '임계치 이탈(Deviation from Norm)'에 가중치를 부여한다.
단순한 높은 수치는 불안감을 유발하지 않습니다. **"최근 몇 주 대비 변화가 비정상적으로 급격하다"**는 것이 핵심입니다.

$$
SAI_t = W_{Log} \cdot (\text{LVI}_{t} / \text{LVI}_{t-1}) + W_{Reg} \cdot |\text{Gap Rate}_{t}| + W_{En} \cdot (1 - \frac{\text{Normal Capacity}}{\text{Current Load}})_{t}
$$

**세부 로직 가설:**

1.  **정규화 ($\text{LVI}, \text{Gap Rate}$):** 각 지표를 0과 1 사이의 값으로 정규화합니다. (예: 지난 3개월 평균 대비 현재 값이 얼마나 벗어났는가?)
2.  **변동성 가중치 ($W$):** $W_{Log}, W_{Reg}, W_{En}$에 초기 가중치를 부여합니다. (예: 물류 마비($W_{Log}$)의 공포를 가장 높게 설정하여 0.4, 법규 Gap($W_{Reg}$)를 0.3, 에너지 취약성($W_{En}$)을 0.3으로 설정).
    *   ***(개발팀 지시):*** 이 가중치는 콘텐츠 제작 시점의 시장 상황에 따라 유동적으로 조정되는 '가변 계수'로 설계되어야 합니다.
3.  **출력:** SAI 점수가 특정 임계값(Threshold)을 넘으면, **'🚨 경고: 시스템 무결성 위협 감지 🚨'**라는 UI 컴포넌트를 시간 코드에 맞춰 트리거합니다.

### 3. Mock-to-Real 데이터 교체 테스트베드 설계 요건
개발팀은 이 가이드라인에 따라 E2E 통합 테스트 환경을 구축해야 합니다. 목표는 '데이터가 실패하는 과정 시뮬레이션' 그 자체를 서비스화하는 것입니다.

#### A. 시스템 아키텍처 요구사항 (Developer Focus)
1.  **상태 관리:** 모든 데이터 피드(API)의 **현재 상태, 과거 3개월 평균값, 그리고 예상 임계치**를 메모리에 저장하고 관리해야 합니다. (단순 수치 제공을 넘어 '맥락' 제공이 필수.)
2.  **데이터 계층 분리:** API 호출 로직은 반드시 `data_source/` 모듈 내에 격리되어야 하며, Mock 데이터는 이 모듈의 **가짜 응답(Fake Response)**으로 작동해야 합니다.
3.  **Mock-to-Real 전환 스위치:** 개발자 콘솔에서 단일 토글(Switch)만으로 'MOCK' -> 'REAL API CALL'로 전환 가능해야 하며, 전환 시 시스템 오류 메시지(`Connection Error`, `401 Auth Failed`)가 **경고 UI 컴포넌트**로 노출되어야 합니다.

#### B. 데이터 교체 테스트베드 시나리오 (Developer/Designer 협업)
| 단계 | 목표 기능 | Mock 데이터 활용 예시 | Real API 연동 필요 지점 |
| :--- | :--- | :--- | :--- |
| **Mock (개발 초기)** | 시스템의 기본 흐름 검증 및 UI 애니메이션 테스트. | 모든 Metric Payload에 '임계치 미달' 또는 '평균 유지' 값을 고정 입력. | 없음. 오직 프론트엔드 플로우와 타이밍(Timecode)만 검증. |
| **Transition (Mock $\rightarrow$ Real)** | 데이터 실패/불안정성 시각화 테스트. | 임의로 `API Connection Error`를 Mock 응답으로 강제 발생시키고, UI가 이를 '데이터 오류' 경고 메시지로 처리하는지 확인. | 실제 API 인증(Authentication) 및 에러 핸들링 로직 검증. (핵심!) |
| **Real (운영 단계)** | 실시간 구조적 불안감 점수 산출 및 콘텐츠 근거 제공. | 실제 데이터를 받아 SAI 공식에 대입하고, 이 결과가 경고 UI 트리거를 발생시키는지 통합 검증. | 모든 외부 API의 안정적인 호출과 데이터 변환(Normalization) 로직이 필수적으로 작동해야 함. |
