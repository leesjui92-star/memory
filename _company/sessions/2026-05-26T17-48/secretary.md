# ✅ [MASTER CHECKLIST] 통합 시스템 검증 체크리스트 (v1.0 Draft)

**목적:** 숏폼 콘텐츠의 *'시스템적 불안정성'*과 이를 통한 *'기술적 신뢰성(Trust Score)'* 기반 판매 여정을 완벽하게 구현했는지 다각도로 검증합니다.
**참조 대상 에이전트:** Designer, Leo (Video), Developer, Editor (Audio)

## 🕰️ 1단계: 시간코드 및 비주얼 플로우 (Leo & Designer Focus)
핵심은 단순한 영상 재생이 아닌, **'시간 흐름에 따른 결함의 노출(T+Xs)'**을 완벽하게 동기화하는 것입니다.

*   ✅ **[Timecode Sync] 5대 구조적 결함 시퀀스:** 모든 필수 경고 UI가 T+X 초 단위로 정확히 활성화되는지 확인합니다. (예: `T+03s`에서 '데이터 무결성 오류' 발생).
*   ✅ **[Flow Control] Failure State Transition:** 정상 상태(Neon Cyan) $\rightarrow$ 결함 발생(Red/Glitch) $\rightarrow$ 해결책 제시(Deep Black + CTA)로의 색상 및 UI 변화가 논리적이고 급격하게 이루어지는지 확인합니다.
*   ✅ **[Visual Fidelity] Glitch & Distortion:** '시스템 오류'를 시각화하는 Glitch 에셋이 프레임 드랍 없이, 일관된 품질과 타이밍으로 반복되어야 합니다. (단순 필터 적용 금지).

## 💾 2단계: 데이터 및 API 페이로드 검증 (Developer Focus)
콘텐츠의 전문성을 뒷받침하는 핵심 근거가 되는 데이터를 시스템적으로 증명해야 합니다.

*   ✅ **[Data Ingestion] Anomaly Data Flow:** `auto_planner.py`나 외부 소스에서 수집된 '구조적 결함 데이터' (예: 특정 기술의 Rate Limit 초과 그래프)가 누락 없이, 정확한 스키마를 갖춰 API로 전달되는지 검증합니다.
*   ✅ **[Payload Validation] Trust Score 연동:** 최종적으로 계산된 `Trust Score` 값이 영상 내 '권위 확립' 단계에서 팝업 또는 UI 요소에 실시간으로 반영되어야 합니다.
*   ✅ **[System Response] API Mocking 안정성:** 가상의 API 호출(Mock API Call)이 실패하거나 지연되는 시나리오를 연출할 때, 시스템 전체가 크래시 되지 않고 '오류 메시지'만 뱉어내는지 확인합니다.

## 🔊 3단계: 오디오 이벤트 트리거 (Editor Focus)
사운드는 단순 배경음악(BGM)이 아닌, **'불안감 고조의 청각 아키텍처'**를 구축하는 것이 목표입니다.

*   ✅ **[Sound Trigger] 불안정성 증폭:** 결함 발생 시점(T+Xs)에 맞춰 BGM 주파수가 점진적으로 변하거나 (Drone Sound), 특정 주파수의 '삐-' 하는 경고음이 중첩되어 공포감을 조성하는지 확인합니다.
*   ✅ **[CTA Audio] 문제 인식 강조:** 유료 상품(진단 보고서)으로 전환되는 CTA 구간에서는 사운드의 톤이 급격히 안정화되고, 명확한 "해결책"의 느낌을 주도록 설계해야 합니다.
*   ✅ **[Synchronization] 오디오-비주얼 동기화:** 모든 중요한 시각적 이벤트를 설명하는 음성 내레이션 타이밍과 사운드/경고음 트리거가 밀리초 단위로 완벽하게 일치하는지 검증합니다.
