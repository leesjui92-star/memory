## 💡 1. 프로젝트 목표 및 범위
본 하네스는 단순한 기술적 유효성 검증을 넘어, **콘텐츠의 비즈니스 KPI(Key Performance Indicator)** 달성을 최우선으로 하는 E2E 시스템 안정화 도구입니다. 콘텐츠가 '문제 인식 $\rightarrow$ 불안감 고조 $\rightarrow$ 해결책 제시 (CTA)'라는 흐름을 따르도록, 각 시퀀스별 기술적 결함과 비즈니스 임계치를 동시에 검증하는 것이 핵심 목표입니다.

**[핵심 원칙]** 모든 테스트는 **시간 코드 기반의 상태 기계(State Machine)** 방식으로 진행되어야 합니다.

## 🛠️ 2. 개발 전제 조건 (Prerequisites)
개발팀이 작업을 시작하기 전에 반드시 준비/확보해야 할 리소스 목록입니다.

*   ✅ **Asset Schema:** 모든 모듈식 자산은 `v4.0_Asset_Schema_Definition.json`을 준수해야 합니다.
*   ✅ **Core Logic File:** `run_system_validation.py`의 로직을 E2E 오케스트레이터로 업그레이드해야 합니다.
*   ✅ **Fallback Assets:** '오류 코드 피크 지점' 대응용 대체 콘텐츠(Fallback Asset)가 JSON/YAML 메타데이터와 함께 준비되어야 합니다. (A/B 테스트 버전 포함)
*   ✅ **KPI Logic Map:** `FINAL_CTA_CONVERSION_SPEC_V1.0.md`에 정의된 PAI 임계치 및 CTA Time Gap 구간이 개발 로직에 반영되어야 합니다.

## ✨ 3. 주요 기능 목록 (Feature List)
개발팀은 다음의 3가지 축을 중심으로 기능을 구현해야 합니다.

### A. 시간 동기화 오케스트레이션 (Kodari 주도)
*   **시간 흐름 제어:** 입력된 JSON/YAML 페이로드의 시간 코드(`T+Xs`)를 기반으로, 현재 활성화되어야 할 자산(Visual, Audio, Script)을 순차적으로 결정합니다.
*   **상태 추적:** 시스템은 현재 테스트가 어떤 단계(문제 인식 $\rightarrow$ 경고 발생 $\rightarrow$ CTA 전환 대기 등)에 있는지 지속적으로 상태를 기록해야 합니다.

### B. 실시간 유효성 및 실패 모드 처리 (Kodari 주도)
*   **Schema Validation:** 모든 자산이 `v4.0` 스키마와 데이터 타입 규칙을 준수하는지 검증합니다.
*   **Failure Mode Handler:** 예측된 치명적 결함(예: API 호출 실패, Asset 로드 오류) 발생 시, 시스템 강제 종료 대신 **사전 정의된 Fallback Asset으로 즉시 전환**되어야 합니다.

### C. KPI 기반 테스트 로직 (Researcher 주도)
*   **PAI 측정 모듈:** T+10s ~ T+15s 구간에 진입하면 PAI 측정 로직이 활성화되며, 시스템은 해당 구간에서 최소 3가지 리스크 키워드가 연속으로 제시되는지 확인해야 합니다.
*   **CTA 전환 타이밍 체크:** PAI 측정 후, 정의된 CTA Time Gap (T+15s ~ T+20s) 동안 적절한 '해결책' 자산이 활성화되고, 최종적으로 CTA가 배치되었는지 여부를 KPI로 기록합니다.
