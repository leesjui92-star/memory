## ⚙️ 통합 자동화 아키텍처: The Source-to-Omni Pipeline (S2O)

### 1. 필수 기술 스택 및 구성 요소 정의 (Tech Stack & Components)

| 분류 | 도구/API 명칭 | 역할 (Function) | 사용 목적 (Goal) |
| :--- | :--- | :--- | :--- |
| **오케스트레이터** | Make (Integromat) 또는 Zapier | 전체 워크플로우의 트리거 및 순서 제어. 각 모듈 간 데이터 전달 책임. | 시스템 안정성 및 확장성 확보. |
| **LLM 코어 엔진** | Gemini Pro / GPT-4 API | 텍스트 분석, 재가공, 요약, SEO 키워드 추출, JSON 구조화 (출력 형식 통제). | 콘텐츠 지능화 및 다중 플랫폼 최적화. |
| **이미지 생성** | DALL-E 3 또는 Stability AI API | LLM이 도출한 '프롬프트'를 기반으로 고품질 이미지를 자동 생성. | 시각적 완성도 극대화 (매체별 적합성 고려). |
| **CMS/데이터 저장소** | Notion API / Airtable API | 모든 원본 데이터, 재가공된 아웃라인, 이미지 URL, 발행 스케줄을 중앙 집중식으로 관리. | 작업의 투명성과 이력 추적(Audit Trail) 확보. |
| **배포 채널 API** | Blogger/WordPress API, YouTube Data API, Buffer/Sendible API | 최종 콘텐츠를 각 플랫폼에 예약 발행하고 노출을 자동화. | 일관성 있는 배포 및 트래픽 극대화. |

### 2. 데이터 파이프라인 구성도 (Step-by-Step Workflow)

#### **[Phase 0: Trigger & Input]**
*   **트리거:** CMS/Notion에 '새로운 원본 콘텐츠'가 게시되거나, 수동으로 워크플로우가 시작됨.
*   **데이터 입력:** Source Content (제목, 본문 전문, 핵심 키워드 리스트)

#### **[Phase 1: AI 분석 및 구조화 (The Brain)]**
*   **엔진:** LLM API 호출 (Gemini Pro).
*   **입력 데이터:** Source Content.
*   **핵심 작업:** LLM에게 '다중 포맷 JSON 출력'을 요청합니다. 이 단계에서 모든 파생 콘텐츠의 골격이 완성됩니다.
    1.  **SEO/블로그용 구조화:** 블로그 제목 (H1), 메타 디스크립션, 본문 SEO 단락 분할 (H2, H3), 핵심 키워드 밀도 분석 결과.
    2.  **유튜브 스크립트 구조화:** 훅(Hook) / 도입부 / 전개 (챕터별 아웃라인) / 클로징 CTA 형태로 분해된 목차와 각 섹션의 핵심 문구.
    3.  **이미지 프롬프트 생성:** 본문 내용을 기반으로 블로그 삽입용 이미지, 카드뉴스 배경 이미지 등 5~10개의 고화질 Midjourney/DALL-E용 **프롬프트 리스트**.

#### **[Phase 2: 콘텐츠 확장 및 매체 제작 (The Factory)]**
*   **① 비주얼 자산 생성:** Phase 1에서 받은 '이미지 프롬프트 리스트'를 DALL-E API로 순차 호출 $\rightarrow$ 이미지 파일(URL)을 수집.
*   **② 포맷별 최종 콘텐츠 완성:**
    *   **블로그용:** LLM이 재가공한 본문 + 최적화된 이미지 URL 조합.
    *   **유튜브 스크립트:** 아웃라인 기반으로 톤앤매너에 맞는 대본 완성 (TTS 엔진 연동 가능).
    *   **SNS 카드뉴스:** 핵심 메시지(3~5가지)를 추출하고, 이를 바탕으로 간결한 카피와 이미지 URL을 조합.

#### **[Phase 3: 배포 및 모니터링 (The Distributor)]**
*   **오케스트레이션:** Make/Zapier가 각 채널별로 최적의 타이밍과 순서에 맞춰 작업을 실행합니다.
    1.  **블로그 발행:** CMS API 호출 $\rightarrow$ 제목, 본문 전문, 이미지 URL을 업로드 및 **예약 발행**. (필수: 네이버/구글 SEO 메타 정보 삽입)
    2.  **유튜브 배포:** YouTube Data API 호출 $\rightarrow$ 스크립트와 썸네일(이미지)를 붙여 **업로드 예약**.
    3.  **SNS 홍보:** Buffer API 호출 $\rightarrow$ 카드뉴스 요약본과 블로그 링크를 첨부하여 주간 단위로 **교차 홍보 일정 등록**.

### 3. 개발자 관점의 구현 고려 사항 (Implementation Notes)

1.  **에러 핸들링(Error Handling):** 모든 외부 API 호출(특히 이미지 생성, LLM 호출)에는 `try-catch` 로직을 필수로 적용하여 하나의 실패가 전체 파이프라인을 멈추지 않도록 합니다.
2.  **토큰 및 비용 관리:** 콘텐츠 길이가 길어질수록 LLM API 사용량이 폭증하므로, 가장 핵심적인 부분(예: 블로그 본문 구조화)에만 고성능 모델(GPT-4/Gemini Opus)을 사용하고, 단순 재가공에는 저비용 모델을 배정하여 비용 효율성을 높여야 합니다.
3.  **데이터 표준화:** 모든 API 호출 전에 데이터를 `JSON Schema` 형태로 강제하여, 입력 데이터의 형식이 깨지는 것을 원천 차단해야 합니다.
