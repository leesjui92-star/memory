## 🤖 AI 기반 자율 콘텐츠 제작 및 배포 (Self-Publishing) 파이프라인 아키텍처 보고서
### 목표: 인간 개입을 최소화하고, 시장 변화에 대응하여 '지속적으로' 고품질 콘텐츠를 생성/배포하는 시스템 구축.

본 워크플로우는 4개의 주요 계층(Layer)으로 구성되며, 이들이 API 게이트웨이를 통해 연결되는 것이 핵심입니다.

### I. ⚙️ 파이프라인의 4단계 핵심 워크플로우 (Functional Workflow)

| 단계 | 프로세스 (기능적 정의) | 목표 산출물 | 자율성 난이도 |
| :--- | :--- | :--- | :--- |
| **1. 기획 및 스크립팅** | 시장 트렌드 분석 → 핵심 키워드 도출 → 시나리오/내레이션 초안 자동 생성 및 구조화 (훅 설계 포함). | 최종 확정된 `스크립트(텍스트)`와 `콘텐츠 목차/구조(JSON)`. | ★★★☆☆ (데이터 입력 필요) |
| **2. 에셋 생성 및 통합** | 스크립트에 맞춰 비주얼 에셋(장면별 이미지, 영상 클립), 배경음악(BGM), 사운드 이펙트(SFX)를 자동 제작하고 시간축에 배치함. | 타임코드 기반의 `미디어 시퀀스 파일` (컷 리스트). | ★★★★★ (가장 난이도 높음) |
| **3. 후반 작업 및 최적화** | 믹싱(사운드 레벨링, EQ), 색보정(LUT 적용), 플랫폼별 포맷 변환(해상도/종횡비 조정), 자막 자동 생성 및 스타일 적용. | 최종 `완성된 영상 파일` (MP4 등)과 `메타데이터 패키지`. | ★★★★☆ (규칙 기반 반복 작업) |
| **4. 배포 및 수익화** | 목표 플랫폼(유튜브, 틱톡, 블로그 등)의 최신 가이드라인에 맞춰 제목/설명/태그를 작성하고, 예약 포스팅 및 성과 분석을 수행함. | `업로드된 콘텐츠`와 `성과 데이터 로그`. | ★★★★☆ (규칙 기반 반복 작업) |

### II. 🛠️ 필수 기술 스택 및 구성 요소 (Technical Stack Blueprint)

| 워크플로우 단계 | 핵심 기능 컴포넌트 | 추천 기술/API 스택 | 역할 및 설명 |
| :--- | :--- | :--- | :--- |
| **1. 기획 및 스크립팅** | **A. 트렌드 리서치 모듈** | Google Trends API, Reddit API (r/) 등 크롤링 툴, Keyword Research AI (e.g., Ahrefs/SEMrush API) | 실시간 대화체 데이터 분석을 통한 '불안감' 또는 '호기심' 유발 키워드 및 논쟁점 자동 발굴. |
| | **B. 스토리텔링 AI** | GPT-4o (Advanced Prompt Engineering), Claude 3 Opus 등 LLM API | 도출된 키워드를 바탕으로, 서사 구조(Setup $\to$ Conflict $\to$ Resolution)를 가진 스크립트 및 내레이션 자동 생성. |
| **2. 에셋 생성 및 통합** | **C. 비주얼 제너레이터 (이미지/영상)** | Midjourney API 또는 Stability AI (Stable Diffusion), Runway Gen-2 등 영상 생성 AI API | 스크립트의 장면 설명(프롬프트)을 받아, 일관된 톤앤매너(`Neon Cyan`, `Glitch` 등)를 유지하는 시각적 에셋 자동 제작. **(가장 중요한 통제 요소)** |
| | **D. 오디오/음향 엔진** | ElevenLabs API (TTS), Epidemic Sound API (BGM 라이선스 검색), OpenAI Jukebox 또는 기타 사운드 생성 AI | 스크립트를 기반으로 감정 톤이 포함된 내레이션 음성 합성 및 영상 장면에 맞는 저작권 프리 BGM/SFX 자동 매칭. |
| **3. 후반 작업 및 최적화** | **E. 비디오 편집 엔진 (핵심)** | FFmpeg 라이브러리 기반 커스터마이징, Zapier/Make API 연동 워크플로우 | 생성된 모든 미디어를 받아, 스크립트에 명시된 타임코드에 맞춰 컷 편집, 자막 오버레이, 색 보정(LUT)을 자동 적용. **(통합의 중심)** |
| | **F. 메타데이터 모듈** | SEO 최적화 라이브러리 (Python), 플랫폼별 가이드라인 DB | 유튜브 검색 최적화를 위한 제목, 설명(Long-tail Keyword 포함), 태그 묶음을 콘텐츠 내용과 연동하여 자동 생성. |
| **4. 배포 및 수익화** | **G. 스케줄링/분석 모듈** | YouTube Data API v3 (또는 기타 플랫폼 공식 API) | 완성된 영상을 목표 채널에 예약 업로드하고, 업로드 직후 성과 지표(CTR, 시청 시간 등)를 수집하여 다음 기획 단계의 피드백 루프에 재주입. |

### III. 🚀 핵심 기술 요구 사항 및 결론 (Researcher's Insight)

**1. 가장 큰 병목 구간:**
가장 높은 난이도와 자원 투입이 필요한 곳은 **[2단계: 에셋 생성 및 통합]**입니다. AI는 현재 '아이디어(Script)'와 '개별 에셋(Image/Audio)'을 만드는 것은 뛰어나지만, 이들을 일관된 감정선과 논리적 시간 흐름에 맞춰 **'통합하고 제어하는 것'**이 가장 어렵습니다.

*   **💡 해결책:** FFmpeg 같은 로우레벨 라이브러리를 사용하여 모든 미디어와 텍스트 레이어를 *시간(Timecode)* 기준으로 강제 동기화하는 중앙 제어 시스템(Orchestrator)을 반드시 구축해야 합니다. (이는 코다리 에이전트가 맡아왔던 `sync_orchestrator`의 역할과 동일합니다.)

**2. 자율성을 위한 필수 루프:**
단순 제작 자동화를 넘어, **'피드백 기반 학습(Feedback Loop)'**을 시스템에 내장해야 합니다. (→ 4단계 G 모듈)
*   콘텐츠 A가 업로드 $\to$ 시청자 반응 데이터 수집 $\to$ '불안정 요소 점수'(KRS)가 높게 나온 키워드와 패턴을 분석 $\to$ 다음 콘텐츠 기획(1단계 A, B)에 **자동으로 반영**되도록 설계되어야 합니다.
