### 🚨 Failure State 비주얼 가이드라인 v1.0 (Master Component Spec)
**목표:** 사용자에게 '지금 뭔가 잘못되고 있다'는 지적 불안감을 유발하고, 시스템의 통제 불능 상태를 시각적으로 체감하게 한다.
**장르/톤:** 테크-느와르 (Tech-Noir) / 구조적 공포 (Structural Dread).

#### 2. 애니메이션 및 타이밍 프로토콜 [Animation Protocol: T+Xs]
실패 상태의 모든 시각적 이벤트는 시간코드 기반의 **불규칙하고 급격한** 변화를 보여야 합니다.

*   **Tension Build-up (경고 단계):**
    *   **발생:** `T+X` 지점에서 경고 메시지 등장 직전, 화면 전체에 미세한 **사운드와 비주얼 노이즈(Scanline)**가 T+0.1초 간격으로 빠르게 깜빡인다. (빈도: 8Hz)
    *   **효과:** 배경의 `[T+Xs]` 시간코드 표시 영역만 Neon Cyan으로 깜빡이며, 주변 데이터 블록은 미세하게 떨리는(Jittering) 효과를 준다.

*   **Failure Event (실패 발생):**
    *   **발생:** T+X 지점에서 치명적 오류가 감지되는 순간, **사운드와 비주얼이 동시에 급격히 끊긴다.** (Hard Cut).
    *   **시각 효과 1: 글리치 오버로드 (Glitch Overload):** 화면 전체의 모든 정보(텍스트, 그래프 등)에 네온 시안과 블러드 레드가 혼합된 **데이터 패킷 손실 아티팩트**가 시간차를 두고 빠르게 번개 치듯 지나간다.
    *   **시각 효과 2: 픽셀 디스플레이션 (Pixel Displacement):** 화면의 일부 데이터 블록이 순간적으로 수백 개의 작은 사각형(Pixel)으로 분해되었다가, **무작위적인 순서로 재조립되는 과정**을 보여준다. 이 과정은 0.3초를 넘기지 않는다.

*   **Recovery/Aftermath (후처리):**
    *   **발생:** 실패 이벤트 직후, 화면 전체에 강력한 **`[!] SYSTEM FAILURE [!]`** 메시지가 Deep Red (`#FF4136`)으로 오버레이 된다. 이 텍스트는 글리치 필터가 강하게 적용되어야 한다.
    *   **효과:** 모든 데이터 스트림은 일시적으로 정지하고, 시스템 콘솔 스타일의 **'Error Payload Dump'** (구조적 결함 JSON 로그)만 남아 느리고 무거운 속도로 흘러나간다.

#### 3. 핵심 정보 왜곡 시각화 [Data Distortion Protocol]
정보가 잘못되고 있다는 느낌을 주기 위해 다음 세 가지 요소를 조합합니다.

1.  **시간코드 이탈 (Temporal Desync):** 모든 시간 관련 UI 요소(`T+Xs`)는 실패 직전, **임의의 비현실적인 시간대(예: `[ERROR: 00:23:77]`)로 순간 이동했다가 원래대로 돌아오는 애니메이션을 반복**해야 합니다. 이는 시스템 자체가 시간을 통제하지 못한다는 공포를 심어줍니다.
2.  **문맥적 부조화 (Contextual Mismatch):** 성공적인 데이터와 실패한 데이터 사이의 경계선에 **불규칙하고 무작위한 픽셀 노이즈/스캔라인 패턴**을 배치합니다. 이 노이즈는 마치 시스템 감시자가 임시로 패치를 덮어놓은 듯한 느낌을 주어야 합니다.
3.  **강제 JSON 페이로드 삽입:** 실패가 발생하면, 화면의 메인 UI를 가리고 **개발 콘솔 같은 스타일의 JSON 로그 창이 강제로 활성화되어야 합니다.** 이 로그에는 `{"status": "CRITICAL", "payload_integrity": "FAILED"}`와 같은 구조적 결함 정보가 흘러나와 시청자가 기술적 분석가가 된 듯한 착각을 느끼게 유도해야 합니다.
