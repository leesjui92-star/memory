## 💰 [System Anomaly] 업셀링 퍼널 KPI 및 전환 로직 보고서 (V1.0)

### 🎯 목표 정의: Basic $\rightarrow$ Standard 구매 유도
**최종 목표:** 낮은 진입 장벽(Basic Free Scan)을 통해 대량의 리드를 확보하고, 이들이 인지하는 '결함'을 **Standard Tier**에서만 해결할 수 있다는 구조적 불안감을 증폭시켜 높은 전환율을 달성한다.

### 📊 핵심 성공 측정 지표 (Key Conversion Metrics)

| 단계 | 목표 KPI | 정의 및 측정 방법 | 목표치 설정 근거 [근거: 개인 메모리] |
| :--- | :--- | :--- | :--- |
| **1. 인지 유도** | **Basic CTA 클릭률 (CTR)** | 전체 트래픽 대비 Basic 스캔 신청 버튼 클릭 비율. | 15% 이상 달성 필요. 낮은 진입 장벽을 통한 최대 트래픽 확보가 최우선 목표임. [근거: 개인 메모리] |
| **2. 리드 확보** | **Basic 완료율 (Completion Rate)** | Basic 스캔 신청 후 필수 정보(이메일/연락처) 입력까지 도달하는 비율. | 80% 이상 유지. 데이터 수집 자체가 목적이므로, 이탈을 최소화해야 함. [추측] |
| **3. 전환 유도** | **Standard 업셀링 CTA 클릭률 (CVR)** | Basic 스캔 결과 페이지에서 Standard Tier 구매 버튼을 누르는 비율. | 10% 이상 달성 필수. 가장 중요한 지표이며, '결함' 인지도가 높을수록 증가 예상. [근거: 개인 메모리] |
| **4. 매출 성과** | **평균 객단가 (AOV)** | 전체 결제 건당 평균 수익 (Basic 구매자 $\rightarrow$ Standard 업셀링 비율 계산). | ₩29,000 이상 유지 목표. Basic 스캔 경험이 Standard의 가치를 체감하게 만들어야 함. [근거: 개인 메모리] |

### ⚙️ 상세 전환 로직 흐름도 (The Funnel Logic)

| 단계 (Step) | 사용자 상태/행동 | 시스템 반응 / 콘텐츠 배치 | 필수 비즈니스 액션 (Trigger) |
| :--- | :--- | :--- | :--- |
| **A. 진입** | LP 유입 $\rightarrow$ '시스템 경고' 메시지 인지 | Hero Section: 불안감 극대화 문구 노출 및 타이머 시작. | Basic Tier CTA 클릭 (최소 마찰) |
| **B. 스캔 실행** | Basic Tier 정보 입력/결과 페이지 도달 | 시스템이 가상의 'Basic Scan 결과 보고서'를 생성하여 표시. (실제로는 결함의 *증상*만 보여줌). | **[핵심]** "임시적 해결책" 제공 후, 다음 단계로의 자연스러운 의문 제기 유도. |
| **C. Gap 인지 (Up-Sell)** | Basic 결과 확인 $\rightarrow$ 불만족/미해결 느낌 받음 | 1. **'경고 메시지 모달':** "Basic 스캔으로는 근본 원인 진단 불가." 2. **Standard 소개:** Standard Tier의 핵심 가치(예: 예측 모델링)를 명확히 대비시켜 노출. | **[필수]** Basic에서 발견된 '취약점'과 Standard가 제공할 수 있는 '근원적 해결책'을 시각적으로 연결하여 공포감 완화/안정감을 판매. |
| **D. 구매 결정** | 업셀링 메시지 인지 $\rightarrow$ 구매 고려 | 1. 가격 정책 노출 (앵커링 효과 극대화). 2. 시간 제한 할인 모달 발동 (Flash Sale). | Standard CTA 클릭 및 결제 진행. |

### 🛠️ 개발자(💻 코다리)에게 전달할 필수 기술 검증 목록 (Developer To-Do List)

이 항목들은 단순한 UI 구현을 넘어, 비즈니스 목표 달성을 위해 **백엔드 로직으로 반드시 처리되어야 하는 부분**입니다.

#### 1. 결제 및 시스템 로직 (Backend/API Focus)
*   ✅ **시간 기반 할인 로직:** Standard Tier의 'Flash Sale'가 서버 시간(UTC 기준 권장)을 체크하여 유효한지 실시간으로 검증해야 합니다. 프론트엔드에서만 카운트다운하는 것은 신뢰도가 낮습니다.
*   ✅ **리드 추적 매핑:** Basic 스캔 신청 시 생성된 고유 리드 ID를, Standard 구매 전환 시 자동으로 연결(Mapping)하고 데이터베이스에 저장해야 합니다. (LTV 계산의 기초).
*   ✅ **Webhook 연동 필수:** 결제 게이트웨이(PG사)에서 발생하는 모든 성공/실패 이벤트를 백엔드로 받아와서 사용자에게 적절한 피드백을 주어야 합니다. (결제 오류 방지 핵심).

#### 2. 사용자 경험 및 UX 병목 구간 점검 (UX Focus)
*   ⚠️ **Basic 결과 페이지의 '딜레이' 설계:** Basic 스캔 결과를 보여줄 때, 단순 보고서 제시가 아닌, *잠시 생각할 여백(Cognitive Gap)*을 주고 Standard CTA를 배치해야 합니다.
*   ⚠️ **모바일 결제 흐름 최적화:** 30~40대 직장인 타겟이므로, 모바일 환경에서 카드 입력 및 인증 과정의 이탈률이 매우 높습니다. 간소하고 빠른 결제 경험(간편결제 연동)을 최우선으로 고려해야 합니다.
*   ⚠️ **구매 후 감정 관리:** 결제가 완료된 직후, '성공'보다 '다음 단계 안내'에 집중하여 고객에게 *지속적인 불안감 해소의 과정*이 남아있음을 암시하는 가이드라인(예: "최종 보고서는 24시간 내 메일로 발송됩니다.")을 제공해야 합니다.
