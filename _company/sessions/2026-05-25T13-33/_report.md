### 🛠️ 최종 산출물: T+15s~T+30s '진단 플래시' 컴포넌트 키트 (Mobile First)

**목표:** 시청자의 주의를 강제하고, 정보의 전문성을 극대화하여 '문제 진단 요청 리드(Lead)'를 유발하는 최소 기능 단위의 UI 모듈 5가지 정의.
**배경 원칙:** Deep Black (`#0A0A0A`) 배경 위에 네온 시안(`#00FFFF`) 데이터를 오버레이하는 고대비 구조 유지. [근거: Designer 개인 메모리, Self-RAG]

#### 1. 컴포넌트 정의 및 모바일 최적화 (Mobile Adaptation)
| 컴포넌트 명 | 역할/기능 | 필수 포함 요소 | 크기/배치 원칙 (Mobile Vertical) | 근거 |
| :--- | :--- | :--- | :--- | :--- |
| **[A] 시스템 오류 경고창** (System Alert Box) | 핵심 정보 공개 직전, 긴장감 최대화. 모든 모듈의 전후에 사용되어 '시스템이 불안정함'을 암시. | 1. 빨간/주황색 계열의 임시 Accent (`#FF4500` 등). 2. 글리치 애니메이션(Glitch) 필수 적용. 3. 짧고 강렬한 경고 메시지 (예: `[CRITICAL ERROR]`). | 화면 전체 폭에 걸치는 바(Bar) 형태. 하단 중앙 정렬. 텍스트는 최대 4~5 단어 제한. [근거: Designer 개인 메모리, T+15s 지침] |
| **[B] 데이터 파라미터 스트림** (Data Stream Overlay) | 전문 용어와 데이터를 시각적으로 '흐르게' 함으로써 신뢰성 및 복잡성을 부여. | 1. 미세하게 움직이는 코드 문자열(`a, b, c...`). 2. 낮은 채도의 그레이(Low-Saturation Gray)로 배경 처리. 3. 주기적인 노이즈 필터링 효과 (Scanline). | 화면 상단 또는 하단에 가느다란 스트림 형태로 배치. 시선이 자연스럽게 따라가도록 사선 배치 권장. [근거: Designer 검증된 지식] |
| **[C] 진단 플래시 메인 타이포** (Diagnosis Flash Title) | 가장 중요한 메시지('당신은 시스템적 결함을 가지고 있다' 등)를 전달하는 핵심 요소. | 1. 고대비 산세리프 (`Orbitron` 계열). 2. 네온 시안(`#00FFFF`)에 글리치 효과 적용. 3. 노이즈 주파수 변화를 통한 '진동감' 연출. | 화면 중앙 상단 (Rule of Thirds의 1/3 지점). 가장 크고 임팩트 있는 사이즈로 배치. [근거: Designer 검증된 지식, A] |
| **[D] 구조적 결함 시각화** (Defect Visualizer) | 추상적인 개념(예: '시스템 오류', '지식 공백')을 구체화하는 인포그래픽 요소. | 1. 깨진 데이터 블록 형태의 그리드 패턴. 2. 왜곡된 좌표계/격자(Grid) 오버레이. 3. 트랜지션 시간 동안 급작스러운 색상 대비 변화 (Cyan $\rightarrow$ Black). | 화면 중앙을 가로질러 '파괴'되거나, 특정 영역만 사라지는 애니메이션 구조. [근거: Designer 개인 메모리] |
| **[E] CTA/Exit Ramp 모듈** (Action Trigger) | 문제 인식 후 해결책(진단 서비스)으로 연결하는 유일한 탈출구. 구매를 강요하지 않는 질문 형태 유지. | 1. 상대적으로 낮은 채도와 부드러운 전환 효과. 2. '더 알아보기', '자가 진단 필요성' 등 질문형 문구 사용. 3. 배경과 구분되는 미묘한 네온 아우라(Glow). | 화면 하단에 고정된 형태로 배치 (Footer 역할). 시청자의 눈이 자연스럽게 도착하는 위치. [근거: Self-RAG - Exit Ramp 개념] |

#### 2. 기술적 변수 상세화 (T+15s ~ T+30s, Diagnosis Flash)
**A. 글리치/정보 결함 애니메이션 로직:**
*   **노이즈 주파수 변화 범위 (Noise Frequency Range):**
    *   **정상 상태(Normal State):** 4-6Hz의 미세한 스캔라인 노이즈(Scanline)가 지속적으로 적용되어 '관찰 중인 데이터' 느낌을 유지. [근거: Designer 개인 메모리]
    *   **위험 감지 구간 (Warning Trigger):** 주파수 폭이 급격히 10-20Hz로 상승하며, 시청자의 청각적 긴장감(Sound Build-up)과 동기화되어 '신호 과부하'를 표현. [근거: Designer 개인 메모리]
    *   **최고점 (Peak Defect):** 주파수 변화가 불규칙하고 예측 불가하며, 순간적으로 모든 노이즈가 멈추거나(Silence/Blackout) 극단적인 깜빡임(Flicker Rate: 10Hz 이상)을 일으킨 후 다시 시작하는 '충격 요법' 구조를 사용.

*   **왜곡 패턴의 트랜지언트 시간 (Transient Distortion Time):**
    *   데이터 블록이나 타이포그래피가 왜곡되는 과정은 **3~5프레임(Frame)** 이내에 완료되어야 합니다. (너무 길면 지루함 유발). [근거: Designer 개인 메모리]
    *   왜곡의 시작(`T_start`)과 끝(`T_end`) 간 시간 차이($\Delta T = T_{end} - T_{start}$)는 0.2초를 넘지 않도록 제어합니다. 이는 시각적 충격(Impact)을 최대화하기 위함입니다.

**B. 모바일 최적화를 위한 레이아웃 원칙:**
1.  **Vertical Stacking (수직 쌓기):** 모든 정보는 수평적으로 분산되기보다, 중요한 메시지 $\rightarrow$ 근거 자료 $\rightarrow$ 결론(CTA) 순으로 수직 흐름을 따라 배치되어야 합니다. [근거: Designer 개인 메모리]
2.  **Tap Target Simulation:** CTA 모듈([E])은 실제 터치 가능한 버튼처럼 보이도록 시각적 아우라와 명확한 경계 처리를 적용합니다. 이는 '행동 유도'의 직관성을 높입니다. [근거: Figma/UX 원칙]
3.  **텍스트 밀도 제한:** 1초당 화면에 노출되는 전문 용어 또는 데이터 포인트는 최대 3개로 제한하여, 모바일 환경에서 시청자가 정보 과부하를 느끼지 않도록 합니다.
