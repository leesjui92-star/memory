# 🎨 Designer — Developer가 확정한 'Await State'의 기술적 명세(Mock API 데이터 흐름)에 맞춰, 시청자의 지루함을 긴장감으로 전환시키는 3가지 버전의 UI 컴포넌트 세트를 제작하십시오. (1) 일반적인 로딩 스피너 형태를 벗어난, 시스템 결함 느낌을 주는 '데이터 스트림 정체' 애니메이션, (2) 에러 코드가 반복적으로 깜빡이는 '디버깅 루프' 시각화, 그리고 (3) 전반적인 배경에 미세한 노이즈/글리치 효과가 적용된 템플릿입니다. 모든 컴포넌트는 시간코드 기반의 인터랙티브 명세서 형식으로 완성되어야 합니다.

🎨 Designer: 작업 시작합니다.

CEO님의 지시 내용을 확인했습니다. 단순히 '멋진' 애니메이션을 만드는 것이 아니라, **기술적 명세(Mock API 데이터 흐름)**에 맞춰 시청자의 심리 상태를 조절하는 디자인 시스템이 필요하다는 점이 핵심입니다. [근거: CEO의 지시]

이는 제가 그동안 축적해온 테크-느와르 비주얼 가이드라인(`[근거: Designer 검증된 지식]`)과 코다리가 구현할 실패 로직을 결합하여, **'시스템 관찰자 시점(System Observer POV)'**의 인터랙티브 명세서로 완성해야 합니다.

가장 가치 있는 단일 작업은 3가지 요구되는 UI 컴포넌트들을 분리된 개념이 아니라, 하나의 **시간 흐름에 따른 상태 전이(State Transition)**를 가진 통합 디자인 시스템으로 정의하는 것입니다. 저는 이 역할을 주도하여 최종 산출물을 제작하겠습니다.

### 📄 [산출물] Await State 시각화 컴포넌트 세트 명세서 (v1.0)
**파일명:** `assets/design_spec/await_state_components_v1.0.md`
**목표:** 지루함 $\rightarrow$ 시스템적 긴장감 $\rightarrow$ 정보의 전문성 강조

#### ⚙️ 1. 기본 원칙 및 공통 요소 (Global Rules)
*   **배경(Base Layer):** Deep Black (`#0A0A0A`). 배경 전체에 저주파수 노이즈 패턴(`[Frequency: 2Hz]`)을 미세하게 오버레이하여 '시스템 가동 중'이라는 느낌을 유지합니다. [근거: Designer 검증된 지식]
*   **글리치 효과 (Glitch Protocol):** 모든 컴포넌트의 핵심 요소(텍스트, 바운더리)에는 `T+0ms`에 미세한 스캔라인(`[Opacity: 5%]`)을 적용하고, 상태 변화 시점(Transition Point)마다 짧은 디스플레이 지연 효과를 추가합니다. [근거: Designer 검증된 지식]
*   **타이포그래피:** `Orbitron` 계열의 고대비 산세리프체 유지. 모든 텍스트는 활성화 상태일 때만 네온 시안 (`#00FFFF`)으로 빛나야 합니다.

#### 💠 2. 컴포넌트별 상세 명세 (Component Breakdown)

##### A. 데이터 스트림 정체 애니메이션 (Data Stream Stagnation - 'Await')
*   **목적:** API 호출이 성공적으로 시작되었으나, 예상치 못한 처리 단계에서 일시적으로 멈춰 있는 상태를 표현. **(가장 자연스러운 대기)** [근거: Designer 개인 메모리]
*   **레이아웃/구조:** 중앙에 큰 컨테이너 박스(Glassmorphism 스타일) 배치. 이 박스는 투명도를 가지며, 내부에는 데이터 패킷이 흐르는 애니메이션을 구현합니다.
*   **애니메이션 로직 (Timecode Based):**
    1.  `T+0ms`: 좌우에서 네온 시안의 점선(데이터 스트림)들이 3개씩 들어오기 시작합니다.
    2.  `T+500ms ~ T+2000ms`: 데이터 패킷이 중앙 컨테이너를 향해 이동하며, 각 패킷은 `[Metadata: UUID_XXXX]`와 같은 구조화된 데이터를 표시합니다.
    3.  **정체 시점 (Stagnation):** 모든 패킷의 속도가 급격히 늦춰지며(Ease-out Curve), 마지막 패킷이 중앙에 도달하여 **멈추는 순간**, 컨테이너 박스의 테두리 네온 빛이 미세하게 떨리는 진동 효과(`[Frequency: 10Hz, Amplitude: 2px]`)를 일으키며 '처리 중...' 메시지가 깜빡입니다.
*   **색상/효과:** `#00FFFF` (데이터 패킷), `#1A1A1A` (컨테이너 배경).

##### B. 디버깅 루프 시각화 (Debugging Loop - 'Error Potential')
*   **목적:** 시스템이 반복적으로 오류를 확인하고 복구하는 듯한 불안감을 유발. **(긴장감 최고조)** [근거: Designer 개인 메모리]
*   **레이아웃/구조:** 중앙에 텍스트 로그 창(`Terminal Window`) 형태의 인터페이스를 강제 배치합니다. 이 컨테이너는 다크 그레이 (`#1A1A1A`) 배경에 녹색 계열(Neo-Green)의 글자가 깜빡이는 전통적인 터미널 느낌을 차용합니다.
*   **애니메이션 로직 (Timecode Based):**
    1.  `T+0ms`: 로그 창 하단에 커서가 점멸하며 (`Blink: 500ms`), 초기 프롬프트(`> Awaiting Input...`)를 출력합니다.
    2.  `T+100ms ~ T+3000ms`: 임의의 에러 코드가 초당 2회 반복적으로 깜빡이며 스크롤됩니다. (예: `ERROR_CODE_403`, `SYNTAX_FAILURE`)
    3.  **핵심 효과:** 에러 코드를 출력할 때마다, 해당 라인 주변에 짧고 강렬한 **네온 레드 경고 플래시** (`#FF3333`, Duration: 50ms)가 발생합니다. 이는 시스템 오류의 시각적 증거로 작용합니다.
*   **색상/효과:** `#1A1A1A` (배경), `#CCFF99` (로그 글자), **강조 경고:** `#FF3333`.

##### C. 전반적 노이즈/글리치 템플릿 (Ambient Noise - 'Suspense')
*   **목적:** 특정 상태가 아닐 때도 배경에 깔려 끊임없이 긴장감을 유지하는 필터 레이어 역할. **(지속적인 압박감)** [근거: Designer 검증된 지식]
*   **레이아웃/구조:** 모든 화면의 최상위 레이어로 작동합니다. 시각적 요소는 최소화하고, 오직 '불안정한 환경'이라는 느낌을 전달하는 데 집중합니다.
*   **애니메이션 로직 (Timecode Based):**
    1.  `T+0ms`: 배경 전체에 극도로 낮은 투명도의 `[Filter: Gaussian Noise]`를 적용합니다. (Opacity: 2-3%)
    2.  `T+1s ~ T+End`: 무작위로 가로축과 세로축으로 미세하게 색상 이동(Chromatic Aberration)하는 효과를 주기적으로 발생시킵니다. 이 효과는 주로 화면 모서리나 중요 데이터가 나타날 때만 강화됩니다.
    3.  **강화 조건:** 시스템이 '불확실성 해소' CTA 직전에는 노이즈 필터의 강도(Opacity)와 색상 이동 빈도를 2배로 높여 긴장감을 극대화합니다.
*   **구현 참고:** CSS `filter: url(#noise)` 또는 비디오 프레임워크 기반 오버레이 효과로 구현하는 것이 가장 적합합니다.
