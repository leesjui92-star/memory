## ⚙️ [Landing Page Mockup] 비주얼 시스템 및 가이드라인 브리프

### 1. 핵심 원칙 (Design Philosophy)
*   **컨셉:** High-Tech Control Room / Intelligence Dashboard (통제 센터/정보 관제실).
*   **감성:** 미스터리, 긴장감(Tension), 배타적 지식(Exclusivity), 분석적(Analytical).
*   **목표:** 사용자가 '지금의 정보로는 부족하다'는 불안감을 느끼게 하고, 제품을 **필수적인 시스템 접근 권한**으로 인식하게 만든다.

### 2. 컬러 팔레트 및 타이포그래피 스펙 (Technical Specs)

#### 🎨 Color Palette
| 역할 | 이름/코드명 | HEX 코드 | 용도 설명 |
| :---: | :---: | :---: | :---: |
| **배경 메인** | Deep Void Black | `#0A192F` | 모든 배경 및 섹션 분리. (짙은 남색 계열로 순수한 블랙보다 덜 자극적이며 하이테크 느낌 부여) |
| **강조색 (Accent)** | Neón Cyan Protocol | `#33CCFF` | 핵심 데이터, CTA 버튼, 성공/진실의 발견을 나타내는 포인트. (주요 시선 유도) |
| **경고/위기** | Error Crimson Alert | `#FF4B4B` | 문제점(Pain Point), 시스템 오류, 경고 메시지. (긴급성 극대화) |
| **보조 데이터** | Data Gray Panel | `#AAAAAA` | 배경 정보 카드, 부차적인 통계/숫자 표시. (정보 밀도를 높이되 시선 방해 최소화) |

#### ✒️ Typography Rules
*   **주력 폰트 (Headline/Bold):** *Orbitron* 또는 *Montserrat Bold*. (기하학적이고 미래 지향적인 느낌을 주어 전문성 강조.)
    *   사용: 헤드라인, 핵심 메시지, 경고 문구.
*   **본문 폰트 (Body/Data):** *Inter* 또는 Monospace 계열 (예: IBM Plex Mono). (데이터 로그, 코드 블록, 설명 텍스트에 사용되어 '정보' 자체의 느낌을 부여.)
    *   사용: 긴 설명 문구, 리스트 항목, 데이터 차트 레이블.

### 3. Mockup 구조 설계 (Section by Section Wireframe)

#### 🚀 A. Hero Section (The Hook - 가장 중요)
*   **레이아웃:** 좌측에 압도적인 헤드라인(Headline), 우측에 시각적 위기 경고 대시보드를 배치한다.
*   **헤드라인:** Orbitron Bold, Neón Cyan Protocol 색상 사용. 폰트 크기 최대화 (Impact First).
    *   *(예: [경고] 시스템의 블랙홀로 빠지는 치명적인 구멍)*
*   **서브 카피:** Inter Regular, Data Gray Panel 색상. 불안감을 자극하며 문제 제기를 한다.
*   **시각적 요소:** 화면 중앙에 **가상의 '데이터 게이지(Gauge)' 또는 '위험 레벨 바(Risk Level Bar)'**를 배치한다. 현재 레벨이 빨간색 경고 영역에 걸쳐 깜빡이는 애니메이션 효과 필수.
*   **CTA 버튼:** 크고 직사각형의 네온 시안색(`Neón Cyan Protocol`) 배경, 흰색 텍스트. **[제한된 접근 권한 요청]** 같은 문구 사용 (무료가 아닌 '권한' 구매 느낌).

#### 🚨 B. Problem Definition Section (The Gap)
*   **레이아웃:** Grid 기반의 3~4분할 구조. 각 분할은 하나의 '시스템적 결함'을 상징한다.
*   **제목 스타일:** `[Anomaly Detection]` 같은 시스템 로그 형식을 제목으로 사용.
*   **시각화:** 네온 시안색과 에러 크림슨(`Error Crimson Alert`) 색상을 혼용하여 **"정상 범위 밖의 데이터 포인트"**를 보여준다.
    *   *(예: '당신이 아는 지식'은 빨간 경고 라인으로 둘러싸여 있음)*
*   **내용 배치:** 문제점마다 작은 그래프나 차트 형태(Line Chart, Pie Chart)를 삽입하여 '통계적 결함'처럼 보이게 한다.

#### 💡 C. Solution Protocol Section (The Value Proposition)
*   **레이아웃:** 정보의 흐름이 좌측에서 우측으로 이동하는 **'파이프라인' 또는 '처리 과정(Process Flow)'** 컨셉을 사용한다.
*   **핵심 요소:** 제품을 단순히 '강의'가 아닌, **[Protocol]** 혹은 **[System Update]** 같은 명칭으로 포지셔닝한다.
*   **시각화:** Neón Cyan Protocol 색상의 연결선과 아이콘(⚙️)을 사용하여 정보가 오류 지점(빨간색)에서 해결 과정(파란색)을 거쳐 완벽한 해답에 도달하는 과정을 애니메이션으로 보여준다.
    *   **단계 1 (Input):** 문제 인식 → **단계 2 (Processing):** 시스템 분석 → **단계 3 (Output):** 통제 및 자유 확보.

#### ✨ D. Final CTA Section (Urgency & Scarcity)
*   **레이아웃:** 배경을 Deep Void Black에서 살짝 밝은 그레이/블루 계열로 변경하여 시각적 분리 효과를 준다.
*   **메시지 강화:** **"이 정보는 공개되지 않았습니다."**와 같은 배제(Exclusion) 문구를 필수로 삽입한다.
*   **CTA 버튼:** Hero 섹션과 동일한 디자인을 유지하되, 마우스 오버 시 깜빡이는 애니메이션 효과를 추가하여 즉각적인 행동을 유도한다.
